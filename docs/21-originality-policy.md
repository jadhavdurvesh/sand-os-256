# 21 — Originality and naming policy

SAND-256 must define its own register semantics, subfield model, instruction encodings, arithmetic rules, control flow, memory translation, privilege transitions, event model, boot contract, executable format, and ABI.

Existing architectures may be studied to understand trade-offs. Materially derived ideas should be acknowledged and evaluated. Do not copy proprietary code, text, diagrams, or specifications.

Caelvyr, Aru, Aruvane, Keth, Kethline, Orrenfold, Latticefire, and Veyrforge are provisional project names. Their use does not establish global uniqueness or trademark rights.

Originality is demonstrated by the actual specification, emulator, conformance tests, assembler, and ABI—not by terminology alone.
